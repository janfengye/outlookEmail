# iCloud 主号与隐藏邮件地址

Web 顶部的「iCloud 管理」可新增 Apple 主号、人工登录、提交双重验证码，以及同步、创建、停用和删除隐藏邮件地址。管理接口使用 Apple 私有 Web 协议，当前仍需真实账号验收；离线测试不能证明 Apple 当前接受所有流程或会话能长期有效。

## 配置顺序

1. 在普通邮箱导入/编辑中选择 **iCloud**，填写邮箱和 **App 专用密码**。预设为 `imap.mail.me.com:993`，SSL；识别 `icloud.com`、`me.com`、`mac.com`。已有自定义服务器不会因域名识别被替换。
2. 在「iCloud 管理」新增 Apple ID，选择国际区或中国大陆。Apple ID 不一定是收信邮箱，请按账号实际区域选择。
3. 选择已配置的收信账号，或先保持不绑定。绑定账号的主地址/手工别名必须匹配 Apple 目录中的转发目标；不匹配时该隐藏地址会显示冲突，不生成映射。
4. 选择 Web 通道，输入本次 Apple 登录密码，点击「人工登录 / 接管」。若显示等待验证码，输入本次六位双重验证码后提交。Apple 要求接受条款、验证身份等操作时，需先在 Apple 官方页面完成。
5. Web 管理连接可用后点击「同步」。隐藏邮件地址需要 iCloud+；它与“通过 Apple 登录”的 `privaterelay.appleid.com` 中继地址不同。

Apple 登录密码、管理 Cookie/令牌和 IMAP App 专用密码分别保存。管理连接成功不代表 IMAP 密码可用；请在普通邮箱列表中单独验证收信。没有绑定也可管理 Apple 地址，但不能通过本项目读取隐藏地址邮件。

## 地址操作和邮件归属

- 同步只使用经过完整性校验的 Web HME 目录。失败、缺字段、意外分页不会覆盖原有目录；Apple Account 目录属于补充视图，不用其缺项确认删除。
- 创建先生成候选再保留，支持标签、备注。写响应丢失或无法确认时保留「待核对」，先执行只读同步，避免重复创建。仅身份确定、有效、转发目标匹配且无冲突的地址可取信和被项目新领取。
- 停用后撤下托管映射。永久删除要求先停用并再次确认；删除会真实请求 Apple。删除本地主号或解除收信绑定只清理本地映射，不删除普通邮箱、手工别名或 Apple 地址。
- 普通账号编辑里的托管别名只读，请到 iCloud 管理修改。主邮箱、手工别名、临时邮箱或其他主号占用的地址不会被接管。
- 查询托管隐藏地址时，列表在匹配完整收件地址后分页，详情、附件、原始邮件和本地缓存执行相同归属校验。证据来自 To、Cc、Delivered-To、X-Original-To；正文或主题包含地址不构成证据。
- 达到整体超时或扫描上限会明确报告 `scan_incomplete`，不会返回其他隐藏地址的邮件填充页面。停用、解绑、移除后的地址不可回退为完整主邮箱。既有项目记录保留为历史，不能恢复其领取资格。

## 续期与可选自动重登

有效会话会自动续期，独立于 Outlook Token 刷新开关，也独立于自动重登开关。Account 通道成功后按随机 4–6 分钟安排下次读取管理资源，遇更短 TTL 提前执行；Web 通道使用自身的 validate/trust/token 流程。临时故障按 2、4、8、16、30 分钟退避，遵守更长的 `Retry-After`，不会因为网络错误、429 或配额不足重投密码。

自动重登默认关闭。开启需要保存 Apple 原始密码、该主号专用接码 URL 和区域。密码保留首尾空格；秘密字段留空保留，明确勾选清除才删除。关闭自动重登保留配置和已有会话续期；停用主号或绑定邮箱则停止该主号后台请求。

接码接口约定：

```text
AppleID 登录验证码:123456
```

或具有明确字段的 JSON：

```json
{"otp":"123456","received_at":"2026-10-25T00:00:00+08:00"}
```

支持 `otp`、`smsCode`、`verificationCode`、`securityCode`、`appleCode`，也可用带验证码语义的 `message/text/content`。普通 `code` 状态字段、HTML、无语义数字和多组歧义码不会提交。时间可用带时区 ISO 8601 或 Unix 秒/毫秒，不能早于本次验证触发或明显来自未来；没有时间时必须区别于登录前基线。

登录前读取一次基线，触发验证后每 5 秒最多读取 18 次。链接必须公网直连，禁止重定向，限制超时和响应大小，实际 DNS 与连接目标都校验公网地址；不走 Apple 代理、不携带 Apple Cookie。URL 查询参数视同秘密，不回显、不记入日志。每个主号必须配置其自身链接。

自动登录临时失败约 5–6 分钟后重试，逐步增至 30–31 分钟；失败次数和期限跨重启保留。密码错误、身份不符或账户操作暂停为人工处理；替换相关凭据或人工登录后恢复，普通备注不会清空退避。人工登录、停用、关闭自动重登和替换凭据会取消旧任务，迟到验证码/会话不能覆盖人工结果。

退出 Apple 会话会清除管理快照。**自动重登仍开启时，后续会再次登录；持续退出请先关闭自动重登。** 页面读取仅展示本地状态，不触发上游探测。

## 管理接口与备份

主号资源为 `/api/icloud/accounts`，单个主号下提供 `/login`、`/verify`、`/logout` 和 `/aliases`。所有管理接口要求 Web 登录；写操作受 CSRF 保护，普通对外 API Key 不具备 Apple 管理权限。密码、接码 URL 和管理会话均加密保存，读取只返回配置标记；验证码不入库。

普通账号文本导出及 WebDAV 文本备份不是完整 iCloud 备份，不包含 Apple 密码、接码 URL 或会话。完整恢复需同时保留 SQLite 数据库与原 `SECRET_KEY`；桌面版还需保留运行目录中的 `secret_key.txt`。请在停止应用后复制数据库，或使用 SQLite 一致性备份，并妥善保管密钥。密钥不一致或密文损坏会要求重新配置/登录，不将密文当密码使用。

## 降级到旧版本

旧版本没有隐藏地址邮件隔离能力。降级前必须：

1. 停止当前应用，备份数据库和原加密密钥。
2. 在该数据库中执行以下短事务，停止后台资格并撤下本功能拥有的映射：

```sql
BEGIN IMMEDIATE;
UPDATE icloud_accounts SET enabled = 0, config_version = config_version + 1;
DELETE FROM account_aliases WHERE icloud_alias_id IS NOT NULL;
COMMIT;
```

3. 再启动旧版本。保留普通收信账号、手工别名和 iCloud 独立表；以后升级回来可重新启用、登录并同步，不需要删除历史记录。

不要在旧版本中把隐藏地址导入为普通手工别名来代替托管关系，否则它没有本变更的收件归属限制。

## 排障与验收边界

「管理连接可用」「IMAP 可收信」「隐藏地址可取信」是不同状态。优先查看通道最近错误、失败次数、下次尝试、地址冲突和收信绑定；不要反复点击创建以排查不确定结果。

参考项目观察到约八小时后管理态可能失效，这是其运行观察，不是 Apple 官方固定期限，也不是本项目的连续运行结果。本项目真实登录、地址生命周期、跨重启和跨观察窗口续期验收仍未完成，不能承诺永久免验证。协议依据及离线/构建结果见 OpenSpec 变更 `add-icloud-mail-management/research.md`。
